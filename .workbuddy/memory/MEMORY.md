# SwiftWeekly 项目长期约定

## 周报文件结构（固定模块顺序）

`## 前言` → 期数、寄语、`> 本期精选速览`（四项：新闻和社区 / 提案 / Swift 论坛 / 推荐博文）→ `## 话题讨论` → `## 新闻和社区` → `## 提案`（通过的提案 / 正在审查的提案）→ `## Swift论坛` → `## 推荐博文`（三篇，各自带摘要）→ `## 关于我们`

## 格式约定（重要）

- **不写 H1 文章标题**：正文一律从 `## 前言` 起。文章名字（`… ｜ Swift 周报 Issue N`）是微信公众号推文标题，只在回复中给出，不写入 md
- **`## Swift论坛` 无空格**：105 期之后统一此写法
- 提案条目格式：`[SE-XXXX](url "SE-XXXX")\n**提案名** 提案已通过/正在审查。`（注意是单空格）
- 话题讨论：导语 + `**加粗提问**` + 编号选项（通常 4-5 项）+ 结尾引导语
- 精选速览四项必须全部填写摘要，不留空

## 整理周报时的常见待修项

用户粘贴的素材常出现这些问题，整理时应处理：

- 精选速览后三项留空，需根据正文补全
- 重复/错位的标点（如粘贴残留的 `"。**…**`） 
- 链接 URL 前缀错误（`hhttps://`）、标题多字（如 `SSwift`）
- 标题前后多余空格、多余双空格
- 正文保留用户原意与原文，只做最小必要修复，不擅自改写内容

## 话题讨论选题

用户有时会自己提供话题内容（优先保留）；若未提供，则按当期国际科技互联网热点生成热点话题，并给 4 项左右平衡的选项（含正反方）。
